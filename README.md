1-1) orthodox canonical form  
클래스를 만들 때 기본적으로 구현해야 하는 4가지 함수를 의미하며 객체의 올바른 생성, 복사, 소멸을 보장하기 위해 꼭 필요합니다.  
~~~ c++
class MyClass {
public:
    MyClass();                                    // 1. 기본 생성자
    MyClass(const MyClass& other);                // 2. 복사 생성자
    MyClass& operator=(const MyClass& other);     // 3. 복사 대입 연산자
    ~MyClass();                                   // 4. 소멸자
};
~~~

복사 생성자와 복사 대입 연산자는 언뜻 보면 비슷해 보이지만 차이점이 있습니다. 가장 큰 차이점은 복사 연산자는 기존 객체를 복사하여 새로운 객체를 만들지만 복사 대입 연산자는 기존 객체를 기존 객체에 복사한다는 것입니다. 이 사실로부터 발생하는 중요한 차이점이 하나 더 있는데 복사 생성 연산자의 경우 자기 대입 확인을 필수적으로 해야 합니다.  
그 이유에 대해 설명드리겠습니다. 복사 대입 연산자는 기본적으로 기존 리소스를 먼저 해제하고 새로운 리소스로 대체하는 작업을 수행합니다. 그런데 만약 자기 자신의 리소스를 자기 자신이 복사 대입 연산을 한다고 가정해봅시다. 아래와 같은 모습이 될 것입니다.  
~~~ c++
MyClass a;
a = a;
~~~
앞서 복사 대입 연산자는 기본적으로 기존 리소스를 먼저 해제하고 새로운 리소스로 대체한다고 설명한 바 있습니다. 그러나 위와 같은 상황에서는 자기 자신의 리소스를 해제하고 그 해제된 리소스를 복사하려고 시도하게 됩니다. 비유적으로 설명하자면 "hello world"라고 적힌 종이가 있을 때 이 문장을 지워버리고 지운 자기 자신의 내용을 베끼게 되는 것입니다. 그렇습니다. 애먼 데이터만 영구히 삭제되는 상황이 발생합니다. 그렇기에 아래와 같이 자기 대입 체크를 꼭 해줘야만 합니다.  
~~~ c++
    MyClass& operator=(const MyClass& other) {
        if (this != &other) {  // 자기 자신 대입 체크
            // 기존 리소스 정리
            // 복사
        }
        return *this;
    }

~~~ 

1-2) operator overloading  
기존 연산자(+, -, *, / 등)에 사용자 정의 타입에 의한 새로운 의미를 부여하는 것입니다. 주로 클래스 간의 연산을 정의하기 위해 사용됩니다.  

1-3) 왜 부동 소수점은 계산상 오차가 발생하는가?  
수학적으로 그럴 수밖에 없기 때문입니다. 10진법 형태의 정수값은 컴퓨터에서 사용하는 2진법으로 완벽하게 변환될 수 있습니다. 그러나 소수점 이하의 10진법 소수들은 2진법으로 완벽하게 변환할 수 없습니다. 예를 들어 10진수 0.1을 2진수로 변환하면 0.0001100110011001100110011..과 같이 무한히 반복되는 순환소수가 되어버립니다. 컴퓨터의 저장공간은 한정되어 있기 때문에 결국 어느 순간에는 끊어줄 수밖에 없는데 바로 이때 아주 미세한 오차가 발생합니다. 이것이 컴퓨터에서의 부동 소수점 연산이 항상 정확할 수 없는 근본적인 이유입니다.
